## 2026-11-08 - Step 5b: intersection prefetch, no empty tiles at the bottom (owner decision)
Owner request (final): "enhance the intersection scrolling so that the user never sees the empty or loading tiles at the bottom of the page as he scrolls". This is an owner-approved BEHAVIOUR CHANGE that SUPERSEDES the earlier owner answer "next-page trigger as before" (Step 5: scroll -> 600 ms debounce -> sentinel visible with rootMargin 0 -> `append()`, no prefetch). BC-09 and BC-25 carry dated notes; new BC-31. Approved by: owner (chat); the design choices below are mine and open to review.
- Design. (1) Trigger: `src/components/movie-list/use-prefetch.ts`. One IntersectionObserver on the zero-height sentinel (root = the scrollbar section, rootMargin = 3 viewport heights in px from the section height, rebuilt on resize) wakes the loader; the same check (`sentinel.top <= root.bottom + 3 * height`, synchronous, because the observer only fires on a change) also runs when a page arrives and on every scroll frame. No debounce. At most 2 requests in flight, at most 8 pages in a row without a scroll (tall screens keep loading until the sentinel is beyond the margin, bounded), failure backoff 1 s, 2 s, 4 s .. 15 s (a success inside the backoff window does not reset it), "end" stops requests, a shorter list (page 1 reloaded) re-arms. The loader does not request while a page-1 load is in flight or the list is not the route's category (new App state `loading`, props `loadedType` / `loading`): otherwise a prefetched page could be appended to a list that the page-1 response is about to replace (found by reasoning about the stale `append` closure, which would then overwrite the reloaded list). (2) Ordered pipeline: `src/use-page-pipeline.ts`, used through the new `loadMore` prop. The legacy `append` (hidden Show More, BC-10) is unchanged: it reads list and counter from its render closure, so it cannot run twice at once, and a single in-flight page capped the supply at one page per network round trip (measured with the first single-flight version: with api 300-800 ms it still showed 148 blank frames and 51 frames with the list end in view). The pipeline keeps refs, shares the page counter (BC-05 quirk: not reset per category; advanced with `Math.max`), commits pages strictly in order (an early page waits in a stash), queues a failed page for retry (later pages stay stashed: no duplicate request, no skipped page), learns `total_pages` from every response (and from the page-1 reload) and stops there (or at an empty page); TMDB's 500-page cap is assumed from the API docs, not checked live. (3) Windowing (`use-windowing.ts`): overscan asymmetric, 1.75 viewports ahead and 0.5 behind in the scroll direction (last direction kept when idle), visible rows always mounted, cap 108 mounted tiles (BC-24 bound 120), so tiles are mounted and their posters requested well before they enter the viewport. (4) Pre-warm: `poster-preloader.ts` fetches and decodes (`new Image()`, `decode()`) the posters just beyond the mounted window (1.5 viewports) and the predicted landing zone of a fling (offset + per-frame delta / smooth-scrollbar `damping`, because smooth-scrollbar moves momentum * damping per frame), 6 at a time, at most 36 held, the queue is replaced on every change (far posters are skipped); mounted tiles keep `decoding="async"` and no `loading="lazy"`; `fetchpriority` is not used. - Limits (honest).
